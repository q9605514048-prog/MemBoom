# MemBoom для Windows

В версии 0.9 первый запуск предлагает «Создать аккаунт» и «Войти». После успешного входа приложение сохраняет доступ через Windows DPAPI текущего пользователя и автоматически открывает хранилище при следующих запусках. Для старого хранилища один раз потребуется прежний мастер-пароль; записи не удаляются. Если пользователь не завершил вход, вышел или срок сессии закончился, снова появляется выбор. Локальный выход работает и без сети; отзыв токена на сервере выполняется при доступном соединении. Смена мастер-пароля обновляет защищённый доступ для следующего запуска.

Нативное Windows-приложение на WinForms / .NET 10. В интерфейсе — ночная красно-золотая палитра, без чиби и без встроенного веб-сайта.

В версии 0.6 главный экран получил боковую навигацию, округлые кнопки с плавной подсветкой, переход между разделами и отдельный раздел «Заметки». Анимация отключается при выключенных анимациях Windows и высокой контрастности.

## Возможности

- Мастер-пароль, автоблокировка после пяти минут бездействия, блокировка при сворачивании и блокировке Windows.
- Аккаунты с категориями и произвольными именованными полями; добавление, изменение и подтверждение удаления.
- Поиск, фильтр категорий, избранное, генератор паролей.
- Скрытие секретных значений, отдельное копирование и очистка собственного значения из буфера через 30 секунд.
- Автоматическое локальное сохранение зашифрованного хранилища. Предыдущая версия также остаётся зашифрованной.
- Зашифрованные резервные копии в формате Android/веб-клиента. Импорт объединяет записи; отличающиеся записи с одинаковым ID сохраняются отдельно, повторный импорт не создаёт копии совпадающих записей.
- Смена мастер-пароля с проверкой текущего.
- Ручная синхронизация с MemBoom API: предпросмотр серверной копии, загрузка, отправка или объединение; защита от перезаписи изменившейся серверной версии.
- Регистрация отдельного устройства через административный токен и сохранение подключения в локальном зашифрованном хранилище.
- Список устройств и отзыв доступа к API с подтверждением.
- Отдельные заметки: многострочный редактор, поиск по заголовку и тексту, закрепление, редактирование и удаление с подтверждением.

## Заметки

Раздел «Заметки» открывается в боковом меню. Создайте заметку, задайте название и текст, при желании закрепите её. Поиск работает по заголовку и всему тексту; закреплённые заметки располагаются первыми. Изменения записываются кнопкой «Сохранить заметку»; при обычном закрытии редактор предупреждает о несохранённом тексте. Блокировка приложения закрывает редактор и убирает его текст с экрана, несохранённый черновик при этом не сохраняется.

Заметки шифруются вместе с локальными аккаунтами, переживают перезапуск и смену мастер-пароля. Они также доступны на телефоне и сайте; сетевая синхронизация обменивается аккаунтами и сохраняет локальные заметки без изменений.

При экспорте можно включить заметки в полную зашифрованную копию для Windows 0.6+, Android 0.3+ и обновлённого сайта или выбрать только аккаунты. Старые клиенты могут не прочитать полную копию или пропустить заметки. Повторный импорт совпадающих заметок не создаёт дубликатов; отличающиеся версии с одним ID сохраняются отдельно. Настройки подключения в переносимые копии не входят.

Локальное сохранение работает офлайн. Для обмена доступны зашифрованные файлы и кнопка «Синхронизация».

## Синхронизация

Укажите адрес своего MemBoom API (например, `http://127.0.0.1:8788` для локального сервера), токен устройства и пароль синхронизации. Для удалённого сервера нужен HTTPS; пути, параметры и учётные данные в адресе не допускаются. Адрес сам по себе не запускает сервер.

Если токена устройства ещё нет, нажмите «Зарегистрировать ПК», задайте название и введите административный токен своего API. Сервер создаст отдельный токен устройства; он подставится в окно синхронизации. Административный токен используется только для этого запроса и не сохраняется. Если ответ потерян, устройство могло быть создано — перед повтором проверьте список устройств на сервере.

«Сохранить подключение» сохраняет адрес и токен устройства внутри локального зашифрованного хранилища под мастер-паролем. После перезапуска достаточно ввести общий пароль синхронизации: он не сохраняется. При смене локального мастер-пароля подключение перешифровывается вместе с аккаунтами. Экспорт и синхронизация передают только аккаунты, без настроек подключения. Старые локальные хранилища читаются и переводятся в новый формат при сохранении.

«Забыть подключение» удаляет настройки из текущего хранилища. Это не отзывает токен на сервере; предыдущая зашифрованная локальная версия может содержать старое подключение. При ручном вводе сохраняйте отдельный токен устройства, а административный вводите только в окнах регистрации и управления устройствами.

### Список устройств и отзыв доступа

В окне синхронизации нажмите «Подключённые устройства», введите административный токен и обновите список. Отображаются название, состояние, дата создания и ID; токены других устройств сервер не возвращает. Текущий ПК отмечается, если его ID сохранён при регистрации. Административный токен не сохраняется.

Выберите активное устройство и нажмите «Отозвать доступ». После подтверждения сервер перестанет принимать его токен. Отозванные устройства остаются в списке, повторный отзыв через интерфейс недоступен. Отзыв не удаляет аккаунты из общего хранилища и не стирает локальные данные на потерянном устройстве. Если отозвать собственный ПК, его сохранённое подключение останется, но синхронизация перестанет проходить авторизацию; зарегистрируйте новый токен или забудьте подключение.

После запроса обновите список, чтобы проверить состояние. Если сеть прервалась, отзыв уже мог быть принят сервером. При закрытии окна или блокировке хранилища ожидающий ответ не отображается в новой сессии.

Пароль синхронизации должен совпадать с паролем, которым зашифрована серверная копия, например с паролем синхронизации Android. Он может отличаться от локального мастер-пароля Windows. Нажмите «Проверить сервер»: приложение загрузит и расшифрует копию, покажет ревизию и количество записей.

- «Загрузить с сервера» заменяет локальные записи; предыдущая зашифрованная локальная версия остаётся в `.previous`.
- «Отправить локальные» заменяет серверную копию после подтверждения.
- «Объединить и отправить» сохраняет обе отличающиеся записи, отправляет результат и сохраняет его локально. Удалённые на одном устройстве записи при таком объединении могут вернуться с другого.

При конфликте ревизий обновите предпросмотр. Сетевой сбой не меняет локальные данные; если ответ на отправку потерялся, сначала проверьте сервер, поскольку он мог уже принять запрос. При блокировке приложения окно обмена закрывается, ожидающий ответ не применяется к новой сессии. Передаются только зашифрованные данные, а также токен авторизации. Перенаправления отключены, размер и время ответа ограничены.

Это ручная синхронизация. Фонового обмена и автоматического отслеживания удалений пока нет. Серверный лимит запроса — 1 МБ; для больших хранилищ используйте файлы резервных копий.

## Запуск

Готовая portable-сборка находится в `artifacts/windows/portable/MemBoom.exe`. Она включает .NET и не требует установки SDK. Распакуйте portable ZIP в отдельную папку и запустите EXE. При первом запуске создайте мастер-пароль.

Пользовательские данные: `%LOCALAPPDATA%\MemBoom\vault-v1.json`. Последняя предыдущая версия: `vault-v1.json.previous`. Перенос самой папки portable не переносит данные — используйте резервную копию.

Мастер-пароль и пароль резервной копии допускают от 4 печатных ASCII-символов без пробелов. Аккаунтные пароли и значения полей не ограничиваются этим правилом. Мастер-пароль не отправляется на сервер. Отдельный пароль MemBoom передаётся серверу при регистрации и входе и не записывается в открытый файл.

## Исходники и проверки

Полная сборка с проверками, проверкой интерфейса и упаковкой: `./tools/windows/build.ps1` из корня проекта. Скрипт использует локальный SDK из `.tools/dotnet`, если он установлен; иначе — `dotnet` из PATH.

Интеграционная проверка `node tools/windows/verify-sync.mjs` запускает настоящий сервер на свободном временном порту и использует только синтетические записи. Перед ней соберите `Tests/MemBoom.CoreChecks.csproj` в Release. Для другого SDK задайте `MEMBOOM_DOTNET`. Node.js нужен для сборочных проверок, в portable-приложение он не входит и для запуска EXE не требуется.

- `Core/` — модель, portable crypto, сохранение и миграция формата.
- `App/` — нативные окна, редактор и управление сессией.
- `Tests/` — исполняемые проверки без стороннего тестового фреймворка.

```powershell
dotnet run --project clients/windows/Tests/MemBoom.CoreChecks.csproj -c Release
dotnet build clients/windows/App/MemBoom.Windows.csproj -c Release
dotnet publish clients/windows/App/MemBoom.Windows.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -o artifacts/windows/portable
```

Проверка интерфейса на отдельном синтетическом профиле:

```powershell
dotnet clients/windows/App/bin/Release/net10.0-windows/MemBoom.dll --ui-smoke artifacts/windows/qa
```

Этот режим не обращается к обычному пользовательскому профилю. Он сохраняет тестовый зашифрованный vault, отчёт `ui-check.json` и изображение интерфейса `windows-preview.png`. Проверяются список записей, категории, поиск, избранное и открытие редактора. Снимок через WinForms DrawToBitmap может неполно отображать нативные элементы ComboBox.
